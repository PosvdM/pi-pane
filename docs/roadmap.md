## MVP 范围

- 服务端：会话托管（每个主会话一个 pi RPC 子进程）、会话列表、鉴权、WebSocket 事件分发与重连、慢客户端处理、空闲回收、附件存储。
- 前端：会话列表与树、聊天视图（Markdown、思考折叠、工具卡片、edit 差异）、输入框（发送、steer、follow-up、中止、图片占位符）、模型与 thinking 选择、用量与费用、扩展 UI 对话框。
- pane-bridge：图片顺序还原、多题表单通道。
- 插件接口：插件加载、树、会话视图、面板、动作、表单、通知。
- 与 pi-agora 的 pane 插件联调：子会话树、实时流、存档查看、“待处理”、返工和停止、召集会议。

## 明确不做

- 终端、Git 面板、文件编辑器、canvas、设备中心、审批规则引擎、定时任务。
- 子代理、会议等业务逻辑（由插件提供）。
- 第三方插件的前端代码、插件市场。
- 第二种会话驱动（进程内 SDK）。
- 公网访问、多用户、多端协同编辑。
- 恢复到会话的任意分支。

## 主要风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| `message_end` 替换的时机或范围与预期不符 | 图片顺序无法还原 | P0 第一项验证；不通过时改用降级方式，并推动上游支持有序内容（需另行批准） |
| pi 升级改变 RPC 或扩展 UI 协议 | 托管和对话框失效 | 锁定 pi 版本范围；关键路径写集成测试 |
| 同一会话在终端和 pi-pane 同时运行 | 会话文件被两个进程写入 | 打开前检查最近修改时间并提示；无法完全避免 |
| 用户扩展在 RPC 模式下行为不同 | 部分扩展功能不可用 | 依赖 pi 的 RPC 降级；在文档中列出已知不支持的方法 |
| 集成协议两边不同步 | 插件显示错误 | 协议只在 pi-agora `docs/integration.md` 定义；版本协商；插件契约测试 |
| 前端体积随功能增长 | 违背轻量目标 | 设打包体积预算，CI 检查 |
